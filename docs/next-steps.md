# 남은 일 우선순위 (판단만 정리, 실행하지 않음)

2026-11-26 기준. 위에서부터 먼저 하기를 권한다. **PC** = 사용자가 자기 PC에서 해야 하는 일 (DB·키·개인 파일이 PC에만 있음), **코드** = 코드 수정으로 할 수 있는 일.

## 1. 지금 바로 (앱이 제대로 동작하기 위한 것)

| 순위 | 할 일 | 구분 | 왜 먼저인가 |
|---|---|---|---|
| 1 | Eclipse에서 Pull → Gradle Refresh → 앱 다시 실행 | PC | 최근 병합(영양 퀴즈, PDF 대기 화면, 표시 버그 수정)이 PC에 들어가야 나머지를 확인할 수 있다 |
| 2 | `HEALTH_DATA_KEY` 새로 만들어 `.env`에 넣기 | PC | 검진 수치 암호화 키. 실제 검진을 저장하기 **전에** 정해야 한다 (나중에 바꾸면 이전 저장값을 못 읽는다) |
| 3 | `./gradlew importData --args="load-meals"` (필요하면 `load-recipes`도) | PC | 식사 조합 후보에 포화지방·식이섬유 값이 들어가야 해당 목표와 영양 퀴즈(포화지방·식이섬유)가 제대로 나온다 |

## 2. 이번 주 (결과의 정확도)

| 순위 | 할 일 | 구분 | 이유 |
|---|---|---|---|
| 4 | `ai-translate step` / `tip` 를 하루 한도 안에서 이어 실행 → `translations-en.csv` 커밋 | PC | 영어 화면의 조리 순서·저염 팁이 아직 한국어로 보인다. 무료 한도(하루 약 20회) 때문에 며칠 나눠야 하므로 일찍 시작할수록 좋다 |
| 5 | `data/goldset/ingredient-roles-check.csv`에 O/X 적기 → `roles` 다시 실행 | PC | 기름·설탕 역할 판단의 정확도 수치를 발표에 쓸 수 있다 |
| 6 | `checkup-rules.csv` 기준값을 출처와 대조 | PC | 판정·목표 추천의 근거. 사람이 확인했다는 기록이 필요하다 |
| 7 | 실제 브라우저에서 영양 퀴즈·PDF 대기 화면 한 번씩 확인 | PC | 자동 테스트는 화면에 요소가 있는지까지만 본다. 실제 클릭 흐름은 사람이 봐야 한다 |

## 3. 시간이 나면 (코드 정리, 동작 변화 없음)

| 순위 | 할 일 | 구분 | 이유 |
|---|---|---|---|
| 8 | `messages.properties`와 `messages_ko.properties` 하나로 합치기 | 코드 | 같은 내용 두 벌 → 한쪽만 고쳐 어긋날 위험 ([합치기 제안](code-files.md#13-합칠-수-있는-파일-제안-제안만-아직-합치지-않음)) |
| 9 | 검진 백그라운드 작업(AI·PDF) 공통 코드로 묶기, 대기 화면 파일 이름 `health/wait.html`로 | 코드 | 중복 제거, 이름과 역할 일치 |
| 10 | 게임 규칙 시험(`node src/test/js/nutrition-game.test.js`)을 Gradle `test`에 연결 | 코드 | 지금은 손으로 실행해야 한다. 연결하면 JS 규칙이 깨질 때 자동으로 알 수 있다 (PC에 Node.js 필요) |
| 11 | 대체 규칙 불일치 8건(보류) 다시 검토 | 코드 + PC 확인 | 보류 상태라 추천에 안 쓰인다. 확인하면 대체 후보가 늘어난다 |

## 4. 하지 않아도 되는 것 (판단)

- 영양 퀴즈 서버 순위표: 추가 점수 항목(별도 프로그램)은 이미 충족. DB를 더 쓰게 되어 "DB와 관련 없는 프로그램" 취지와도 멀어진다.
- 강의 자료 방식으로 되돌리기(인터페이스+Impl, 공개 업로드 폴더 등): [course-alignment.md](course-alignment.md)에 이유를 적어 두었고, 보안·구조상 지금 방식이 낫다.
- 결제 연결(Gemini 유료): 무료 등급으로 충분하고 비용 위험이 있다.
